## Slide 3: Target users and the current journey

| User | Role | Current experience |
|---|---|---|
| **SDP township and engineering teams** (primary) | Decide on ponds, drains and phasing | Rely on separate drawings and agency advice; cross-boundary water behaviour is not visible |
| **Councils and JPS** (secondary) | Maintain drains and rivers | Receive complaints after flooding; unclear which agency owns which asset |
| **Residents and residents' associations** (beneficiaries) | Live with the flooding | Learn about heavy rain late; do not know whom to contact; petition after the event |

**Today's journey:** heavy rain → flooding → residents complain → agencies and developers point at each other → a memorandum → slow, contested fixes.

**With RainReady:** shared view of the catchment and pond capacity → storage gap shown before the storm season → agreed priorities → street-specific advisories when official warnings are issued.

## Slide 4: Solution overview

A shared, neutral **decision-support tool** with four parts:

1. **Catchment view.** Shows how water flows from upstream development to downstream streets and marks low-lying zones, with documented flood spots overlaid.
2. **Retention-pond what-if.** Estimates the storage needed for a design storm and shows how an added or deeper pond changes the gap.
3. **Responsibility map.** Records which agency maintains each drain, pond and river reach, as a "who to contact" reference. This matters because ownership is unclear even to the authorities: over 300 unmanned ponds were identified and only about 55 taken over so far.
4. **Street-level advisories.** Takes official MET Malaysia and JPS warnings and tells affected streets what the warning means for them.

**Design principle:** *decision support under uncertainty, not prediction.* It ranks where to look first and says how sure it is.

---

## Slide 5: How it works (prototype and user journey)

**Prototype screens**

| Screen | What the user sees |
|---|---|
| 1. Catchment map | Terrain-derived flow paths, Setia Alam to BBR, low-lying zones, documented flood spots |
| 2. Pond what-if | Sliders for pond area and depth; a bar showing the storage gap for a chosen storm |
| 3. Responsibility panel | For any drain, pond or river reach: the responsible agency, a contact and a confidence label |
| 4. Advisory | An official warning with the affected streets highlighted and a short action list |

**Under the hood**

- **Inputs:** a bare-earth elevation model (FABDEM), land cover and building footprints, rainfall design values from Malaysia's stormwater manual (MSMA 2), and official warning feeds.
- **Methods:** catchment delineation, volume-balance and rational-method calculations, optionally routed pond calculations.
- **Outputs:** risk bands (low, medium, high), not flood depths.

*Demo plan:* show Screen 1 with the documented flood spots, run the pond what-if live, then trigger a sample advisory.

## Slide 6: Innovation and differentiation

| Existing tool | What it does | What it does not do |
|---|---|---|
| myPublicInfoBanjir and JPS flood forecasting | National river and rainfall monitoring, warnings | Township-scale view across developer and council boundaries |
| MET Malaysia warnings | Weather alerts by district | Street-level meaning for a township |
| Council complaint systems | Record faults after the event | Pre-storm planning or shared asset ownership |
| Academic models (HEC-HMS, HEC-RAS) | Detailed hydrology and inundation | Usable by a township manager without specialist skills |

**What is new**

1. A **cross-boundary** catchment view at **township scale**.
2. A **what-if on retention capacity** that planners can run before building.
3. A **responsibility map** that replaces blame with "who to contact".
4. **Street-relevant advisories** built on official warnings, never replacing them.

**Why it fits the moment:** the state's August 2026 plan covers ponds and dredging but does not mention data sharing or early warning. Upstream (Shah Alam, RM150m) and downstream (Klang, urgent projects; state pond at Taman Mutiara) are funded and planned separately. RainReady sits beneath these programmes as a township-scale layer that lets each party see the others' storage and flow.

## Slide 8: Feasibility

- **Data:** Public elevation, land-cover, building and warning data are available now; see Appendix B.
- **Methods:** Simple, published methods from Malaysia's own stormwater guidance (MSMA 2), reviewed by [TBD: lecturer or mentor].
- **Real starting numbers:** SDP's own booklet gives Wetland Townpark storage (16,000 / 34,000 / 50,000 m³) and the Taman Mutiara pond is about 2 ha, so the what-if starts from published values where they exist.
- **Honest limits:** Terrain error is about 1 m in built-up areas, so results are risk bands, not depths. Other pond volumes, pump rates and the drain network are not public. We state all assumptions in an **assumption ledger** (Appendix C) and compute the **storage required** from public inputs, so existing capacity is a stated input rather than a guess.
- **Data-ready by design:** the tool accepts SDP's drain and pond inventory the moment it is available.
- **Team:** three electrical engineering students (data pipeline, dashboard, alerts, optional sensor demo), one mechanical engineering student (hydrology and pond sizing), one architecture student (blue-green pond and wetland options, visualisation).

## Appendix D: Limitations and how we handle them

| Limitation | Our response |
|---|---|
| Terrain error equals flood depth | Risk bands; compare several elevation models and mark "robust hotspots" where they agree |
| No drain or pond data | Assumption ledger; data-ready design; Phase 0 collects it |
| No calibration data | Back-test against documented flood spots and report the hit rate |
| Contested blame | Show flow paths and capacity, not fault; neutral wording |
| Alert liability | Advisory only, built on official warnings, opt-in, always links to the source |
| Data terms | Use official endpoints only; record every licence |
| Government activity | Complement, not compete: a township layer beneath the state plan |
| Skills | Simple published methods; expert review |
| No site validation | Phase 0 validates on site |
| Sensitivity | Neutral language guide; offer SDP a review |

## Appendix E: Validation approach

1. **Back-test:** does the tool flag the documented flood streets (Jalan Makyong, Jalan Sumazau)? Report "X of Y".
2. **Elevation agreement:** how many high-risk cells hold across two or more elevation models?
3. **Sensitivity:** vary assumed pond depth and rainfall; show how the storage gap changes.
4. **Resident survey:** collect flood reports and the "whom do you contact" question; compare with the map.
5. **Expert review:** a hydrology lecturer or mentor checks assumptions.
